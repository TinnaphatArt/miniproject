01ทำไมต้องตรวจ

ทำไมต้องตรวจการเข้าถึงเว็บไซต์

คนจำนวนมากใช้เว็บด้วยโปรแกรมอ่านหน้าจอ คีย์บอร์ด หรือขยายตัวอักษร ถ้าโค้ดผิดเพียงจุดเดียว ข้อมูลส่วนนั้นอาจหายไปทั้งหมดสำหรับเขา ตารางด้านขวาแสดงว่าผู้ใช้ได้รับอะไร ก่อนและหลังแก้ตามกฎทั้ง 4 ข้อ

  • 1.3 พันล้านคนหรือราว 16% ของประชากรโลก มีภาวะพิการที่มีนัยสำคัญ ที่มา: องค์การอนามัยโลก (WHO), Disability fact sheet, 2023
  • ราว 2.2 ล้านคนคนพิการในประเทศไทยที่มีบัตรประจำตัวคนพิการ ที่มา: ทะเบียนกลางคนพิการ กรมส่งเสริมและพัฒนาคุณภาพชีวิตคนพิการ ข้อมูล ณ 1 ส.ค. 2567

ผู้ใช้โปรแกรมอ่านหน้าจอได้รับอะไร

  1. SC 1.1.1 รูปภาพ

    ก่อนแก้<img src="book1.jpg">อาจได้ยินแค่ชื่อไฟล์ “book1.jpg”
    หลังแก้alt="ปกหนังสือนิทานภาพ"“ภาพ ปกหนังสือนิทานภาพ”

  2. SC 1.3.1 หัวข้อ

    ก่อนแก้<h1> … <h3>“หัวข้อระดับ 1 … หัวข้อระดับ 3” เหมือนระดับ 2 หายไป
    หลังแก้<h1> … <h2>“หัวข้อระดับ 1 … หัวข้อระดับ 2” โครงเรื่องต่อเนื่อง

  3. SC 1.3.1 ช่องกรอก

    ก่อนแก้placeholder="อีเมล"“ช่องแก้ไขข้อความ” ไม่รู้ว่าต้องกรอกอะไร
    หลังแก้<label for="email">อีเมล</label>“อีเมล ช่องแก้ไขข้อความ”

  4. SC 1.4.3 สีข้อความ

    ก่อนแก้สีเทาอ่อนบนพื้นขาว 1.61 : 1 ผู้มีสายตาเลือนรางอ่านไม่ออก
    หลังแก้สีเทาเข้ม #595959 บนพื้นขาว 7.00 : 1 อ่านง่ายขึ้น

คำที่ได้ยินเป็นตัวอย่างโดยประมาณ แต่ละโปรแกรมอ่านหน้าจออ่านต่างกันเล็กน้อย

06วิธีคิดคะแนน

คะแนนคำนวณอย่างไร

ใช้วิธี Failure-Rate Metric (Vigo, Brajnik และ Harper, 2011) ตัวเลขด้านล่างมาจากตัวอย่างในบทที่ 3.7.2 ของรายงาน

  1. 1นับคู่ที่ผ่านและไม่ผ่าน แยกตามหลักเกณฑ์

    ไม่ผ่านผ่านต้องตรวจเพิ่ม

    • SC 1.1.1 ข้อความแทนภาพไม่ผ่าน 2 จาก 4 = 0.50น้ำหนัก 3
    • SC 1.3.1 โครงสร้างไม่ผ่าน 2 จาก 5 = 0.40น้ำหนัก 2
    • SC 1.4.3 ความคมชัดของสีไม่ผ่าน 1 จาก 3 = 0.33น้ำหนัก 2

    คู่ที่ต้องตรวจเพิ่ม 1 คู่ยังไม่นับในตัวหาร จนกว่าผู้ประเมินจะตอบแบบประเมิน

  2. 2ถ่วงน้ำหนัก 3 : 2 : 2

    1.1.1 ×31.3.1 ×21.4.3 ×2

    ความกว้างของแต่ละช่องตามน้ำหนัก ส่วนสีแดงคือสัดส่วนที่ไม่ผ่าน รวมแล้วเป็นอัตราไม่ผ่านถ่วงน้ำหนัก

    (3 × 2/4 + 2 × 2/5 + 2 × 1/3) ÷ 7 = 0.4238

  3. 3แปลงเป็นคะแนน 0–100

    100 × (1 − 0.4238) =

    57.62

    0607590

    ต้องปรับปรุง คะแนนต่ำกว่า 60

    คะแนนเต็ม 100 ไม่ได้แปลว่าผ่าน WCAG ทั้งฉบับ เพราะนับเฉพาะกฎที่ระบบตรวจได้

08เพื่อทุกคน

เว็บไซต์ที่ดี ต้องเข้าถึงได้สำหรับทุกคน

ทั้งสามหลักเกณฑ์ที่ระบบตรวจ ช่วยคนกลุ่มนี้ได้โดยตรง

  • ผู้พิการทางการเห็น ใช้โปรแกรมอ่านหน้าจอฟังข้อความแทนภาพ SC 1.1.1 ข้อความแทนภาพ
  • ผู้ใช้คีย์บอร์ดและโปรแกรมอ่านหน้าจอ นำทางตามหัวข้อ รู้ว่าแต่ละช่องให้กรอกอะไร SC 1.3.1 โครงสร้างและป้ายกำกับ
  • ผู้สูงอายุและผู้มีสายตาเลือนราง อ่านข้อความที่สีคมชัดได้ง่ายกว่า ทุกคนที่ใช้มือถือกลางแดดก็ได้ประโยชน์เช่นกัน SC 1.4.3 ความคมชัดของสี

Web Content Accessibility Guidelines แนวทางของ W3C ที่บอกว่าเว็บไซต์ต้องทำอย่างไรให้ทุกคนเข้าถึงได้ รวมถึงผู้พิการ เครื่องมือนี้อ้างอิง WCAG 2.1 ระดับ A และ AA

เครื่องมือนี้ตรวจอะไรได้บ้าง

ตรวจ 3 หลักเกณฑ์ คือ SC 1.1.1 ข้อความแทนภาพ, SC 1.3.1 โครงสร้างหัวข้อและป้ายกำกับ และ SC 1.4.3 ความคมชัดของสี ด้วยกฎตรวจ 5 รหัส ร่วมกับแบบประเมิน 3 ข้อ

คะแนน 100 แปลว่าผ่าน WCAG หรือไม่

ไม่ คะแนนสะท้อนเฉพาะกฎที่ระบบตรวจได้ และคิดเฉพาะหลักเกณฑ์ที่มีจุดให้ตรวจ ถ้าหน้าเว็บไม่มีรูปภาพเลย SC 1.1.1 จะไม่ถูกนำมาคิด ให้ดูกล่อง “คะแนนนี้คิดจาก … หลักเกณฑ์” ในหน้าผลทุกครั้ง คะแนนนี้ไม่ใช่ใบรับรองความสอดคล้อง

แก้โค้ดแล้ว ผลจะเปลี่ยนเป็นผ่านไหม

แต่ละจุดในหน้าผลมี “ผลหลังแก้” ที่ระบบตรวจซ้ำโค้ดหลังแก้ให้แล้ว และเมื่อแก้โค้ดจริงแล้วกดตรวจอีกครั้ง ระบบจะเทียบกับผลครั้งก่อนว่าแก้ได้กี่จุด เหลือกี่จุด และคะแนนเปลี่ยนเท่าไร

โค้ดที่นำมาตรวจถูกเก็บไว้หรือไม่

ไม่ การวิเคราะห์ทำในเบราว์เซอร์ของคุณ ถ้าเลือกบันทึกผล ระบบส่งเฉพาะค่าสรุปเชิงตัวเลขไป Google Sheets ไม่ส่งโค้ด HTML

ทำไมบางเว็บตรวจสีไม่ได้

ระบบอ่านสีจาก style ที่เขียนไว้ในองค์ประกอบเท่านั้น ไม่อ่านไฟล์ CSS แยก ถ้าเว็บกำหนดสีใน CSS ระบบจะบอกว่าตรวจไม่ได้ แทนที่จะให้ผ่าน

มาตรฐานที่เครื่องมือนี้ตรวจ หมายถึงอะไร

ทั้งสามหลักเกณฑ์อยู่ในหลักการที่ 1 การรับรู้ได้ (Perceivable) ของ WCAG 2.1 คือข้อมูลบนหน้าเว็บต้องนำเสนอในแบบที่ผู้ใช้ทุกคนรับรู้ได้ ระดับ A คือขั้นต่ำที่ต้องมี ส่วนระดับ AA คือระดับที่มาตรฐานส่วนใหญ่ใช้เป็นเป้าหมาย

1พื้นฐาน

WCAG 2.1 คืออะไร

WCAG (Web Content Accessibility Guidelines) คือแนวทางการทำเนื้อหาเว็บให้ทุกคนเข้าถึงได้ รวมถึงผู้พิการทางการเห็น การได้ยิน การเคลื่อนไหว และการเรียนรู้ จัดทำโดย W3C ผ่านโครงการ WAI และเป็นมาตรฐานที่หน่วยงานทั่วโลกใช้อ้างอิง

WCAG 2.1 ประกาศเมื่อเดือนมิถุนายน พ.ศ. 2561 (ค.ศ. 2018) ต่อยอดจาก WCAG 2.0 โดยเพิ่มหลักเกณฑ์สำหรับผู้มีสายตาเลือนราง ผู้ใช้มือถือ และผู้ที่มีความบกพร่องทางการเรียนรู้ รวมเป็น 78 หลักเกณฑ์ ใน 13 แนวทาง ภายใต้หลักการ 4 ข้อ เครื่องมือนี้อ้างอิง WCAG 2.1 ตามขอบเขตของโครงงาน หลักเกณฑ์ 3 ข้อที่ตรวจมีข้อความเหมือนเดิมใน WCAG 2.2

  1. WCAG 2.0ธ.ค. 2551
  2. WCAG 2.1มิ.ย. 2561 · ที่เครื่องมือนี้ใช้
  3. WCAG 2.2ต.ค. 2566

หลักการ 4 ข้อ (POUR) และส่วนที่เครื่องมือนี้ตรวจ

1. Perceivable รับรู้ได้

ข้อมูลต้องนำเสนอในแบบที่ทุกคนรับรู้ได้ เช่น ข้อความแทนภาพ สีที่คมชัด

เครื่องมือนี้ตรวจ 3 หลักเกณฑ์

2. Operable ใช้งานได้

ใช้งานได้ด้วยคีย์บอร์ด มีเส้นโฟกัส มีเวลาพอ

ยังไม่ได้ตรวจ

3. Understandable เข้าใจได้

ภาษาและฟอร์มชัดเจน แจ้งข้อผิดพลาดให้เข้าใจ

ยังไม่ได้ตรวจ

4. Robust รองรับได้

โค้ดถูกต้องตามมาตรฐาน ทำงานกับเทคโนโลยีช่วยเหลือได้

ยังไม่ได้ตรวจ

2ระดับความสอดคล้อง

ระดับ A และ AA คืออะไร

ทุกหลักเกณฑ์มีระดับกำกับ เว็บที่อ้างว่าผ่านระดับ AA ต้องผ่านทุกหลักเกณฑ์ระดับ A และ AA รวม 50 ข้อ ระดับ A 30 ข้อ ระดับ AA 20 ข้อ ส่วนระดับ AAA อีก 28 ข้อเป็นระดับสูงสุดที่ไม่บังคับใช้กับทั้งเว็บไซต์

ระดับความหมายเครื่องมือนี้ตรวจ
ระดับ Aขั้นพื้นฐานที่สุด ขจัดอุปสรรคสำคัญที่ทำให้ใช้งานหน้าเว็บไม่ได้SC 1.1.1 และ SC 1.3.1
ระดับ AAเป้าหมายที่หน่วยงานและกฎหมายส่วนใหญ่ใช้SC 1.4.3
ระดับ AAAระดับสูงสุด ใช้กับเนื้อหาบางส่วนที่ต้องการการเข้าถึงขั้นสูงยังไม่ได้ตรวจ

3ขอบเขต

เครื่องมือนี้ครอบคลุมแค่ไหน

4หัวข้อการประเมิน

หลักเกณฑ์ 3 ข้อที่เครื่องมือนี้ตรวจ

การประเมินแบ่งเป็น 3 หัวข้อตามหลักเกณฑ์ของ WCAG 2.1 แต่ละหัวข้อมีน้ำหนักในคะแนนต่างกัน SC 1.1.1 น้ำหนัก 3 เพราะภาพที่ไม่มีข้อความแทนทำให้ข้อมูลหายไปทั้งหมด ส่วน SC 1.3.1 และ SC 1.4.3 น้ำหนัก 2

5กฎย่อย

กฎย่อย 4 ข้อที่ระบบใช้ตรวจ

ภายใต้ 3 หลักเกณฑ์ ระบบตรวจด้วยกฎย่อย 4 ข้อ (5 รหัสกฎ) แต่ละข้อตัดสินได้ 3 แบบ ไม่ผ่าน ต้องตรวจเพิ่ม ผ่าน และองค์ประกอบที่เข้าข้อยกเว้นจะไม่ถูกนับ

  1. 1ข้อความแทนภาพSC 1.1.1 ระดับ A · R-ALT-01, R-ALT-02

    ตรวจอะไร แท็ก <img> ทุกตัวว่ามีแอตทริบิวต์ alt หรือไม่

    ไม่ผ่าน วิกฤต
    <img src="book.jpg">
    ต้องตรวจเพิ่ม
    <img src="line.png" alt=""> ระบบไม่รู้ว่าเป็นภาพตกแต่งหรือไม่ ผู้ประเมินตอบข้อ CL-1.1.1
    ผ่าน
    <img src="book.jpg" alt="ปกหนังสือนิทานภาพ">

    ไม่นับ ภาพที่มี role="presentation" หรือ aria-hidden="true"

  2. 2ลำดับหัวข้อSC 1.3.1 ระดับ A · R-HEAD-01

    ตรวจอะไร หัวข้อ <h1>–<h6> แต่ละตัวเทียบกับหัวข้อก่อนหน้า ว่าลงลึกทีละระดับหรือไม่

    ไม่ผ่าน ควรแก้
    <h1>…</h1> <h3>…</h3> ข้ามระดับ 2
    ผ่าน
    <h1>…</h1> <h2>…</h2> และย้อนกลับขึ้นระดับบนได้ เช่น h3 ไป h2

    ไม่นับ หัวข้อแรกของหน้า เพราะไม่มีหัวข้อก่อนหน้าให้เทียบ

  3. 3ป้ายกำกับช่องกรอกSC 1.3.1 ระดับ A · R-LABEL-01

    ตรวจอะไร ช่อง <input> <select> <textarea> ว่ามีป้ายกำกับผูกไว้หรือไม่ ผ่านได้ 4 วิธี คือ label for ที่ตรงกับ id, label ครอบช่อง, aria-label หรือ aria-labelledby

    ไม่ผ่าน วิกฤต
    <input type="email" placeholder="อีเมล"> placeholder ไม่นับเป็นป้ายกำกับ
    ผ่าน
    <label for="email">อีเมล</label> <input id="email" type="email">

    ไม่นับ ช่องชนิด hidden, submit, button, reset, image และช่องที่มีแอตทริบิวต์ hidden

  4. 4ความคมชัดของสีSC 1.4.3 ระดับ AA · R-CONTRAST-01

    ตรวจอะไร องค์ประกอบที่กำหนดทั้ง color และ background-color ไว้ใน style คำนวณอัตราส่วนความคมชัดเทียบเกณฑ์ 4.5 : 1

    ไม่ผ่าน ควรแก้
    style="color:#cccccc;background-color:#ffffff" 1.61 : 1
    ต้องตรวจเพิ่ม
    ค่าสีที่อ่านไม่ได้ เช่น transparent หรือสีไล่ระดับ
    ผ่าน
    style="color:#595959;background-color:#ffffff" 7.00 : 1

    ไม่นับ องค์ประกอบที่กำหนดสีไว้ด้านเดียว พื้นหลังที่เขียนแบบย่อ background: และสีที่อยู่ในไฟล์ CSS หรือแท็ก <style>

6การแปลผล

คะแนน 0–100 หมายถึงอะไร

คะแนนบอกว่าในจุดที่ระบบตัดสินได้ มีสัดส่วนที่ไม่ผ่านมากน้อยเพียงใด คิดอัตราไม่ผ่านแยกตามหลักเกณฑ์ แล้วถ่วงน้ำหนัก 3 : 2 : 2 ตามวิธี Failure-Rate Metric ดูตัวอย่างการคำนวณทีละขั้น

  1. ต้องปรับปรุง0–59.99 คะแนนพบข้อบกพร่องที่กระทบผู้ใช้อย่างชัดเจน
  2. พอใช้60–74.99 คะแนนพบข้อบกพร่องพอสมควร ควรแก้ก่อนเผยแพร่
  3. ดี75–89.99 คะแนนพบข้อบกพร่องบางส่วน ควรปรับเพิ่ม
  4. ดีมาก90–100 คะแนนพบข้อบกพร่องน้อยมากในกฎที่ตรวจได้
  • จุดที่ต้องตรวจเพิ่มยังไม่ถูกนับ จนกว่าผู้ประเมินจะตอบแบบประเมิน ระบบไม่เดาว่าผ่าน
  • หลักเกณฑ์ที่ไม่มีจุดให้ตรวจจะไม่ถูกนำมาคิดคะแนน เช่น หน้าที่ไม่มีรูปภาพเลย จึงต้องดูกล่อง “คะแนนนี้คิดจาก … หลักเกณฑ์” ในหน้าผลทุกครั้ง คะแนนสูงจากหลักเกณฑ์เดียวไม่ได้แปลว่าผ่านทั้งหมด
  • 100 คะแนนไม่ได้แปลว่าผ่าน WCAG 2.1 คะแนนสะท้อนเฉพาะกฎย่อย 4 ข้อที่ระบบตรวจ

7ข้อจำกัด

ข้อจำกัดของการประเมิน

  1. ตรวจ 3 จาก 50 หลักเกณฑ์ ของระดับ A และ AA ด้วยกฎย่อย 4 ข้อ หลักเกณฑ์ที่เหลือต้องตรวจด้วยเครื่องมืออื่นหรือโดยผู้เชี่ยวชาญ
  2. ไม่อ่าน CSS และไม่รันสคริปต์ สีที่กำหนดในไฟล์ CSS หรือในแท็ก <style> และเนื้อหาที่ JavaScript สร้างภายหลังจะไม่ถูกตรวจ
  3. ตรวจว่ามี alt แต่ไม่ตัดสินความหมาย เช่น alt="image.jpg" ระบบให้ผ่าน คุณภาพของข้อความต้องให้คนตรวจ
  4. ใช้เกณฑ์ 4.5 : 1 กับข้อความทุกขนาด (WCAG ยอมให้ข้อความขนาดใหญ่ใช้ 3 : 1) และไม่คิดค่าความโปร่งใสหรือสีพื้นที่สืบทอดจากองค์ประกอบแม่
  5. หน้าเว็บที่มีองค์ประกอบน้อยได้คะแนนจากหลักเกณฑ์ไม่ครบ ตัวอย่าง เมื่อตรวจโค้ดของเว็บนี้เองได้ 100.00 แต่คิดจาก SC 1.3.1 อย่างเดียว เพราะภาพทั้ง 4 ภาพเป็นภาพตกแต่ง (alt ว่าง รอผู้ประเมินยืนยัน) และสีทั้งหมดอยู่ในแท็ก <style> หน้าผลจึงบอกเสมอว่าคะแนนคิดจากกี่หลักเกณฑ์
  6. ไม่ใช่ใบรับรอง ผลนี้ไม่ทดแทนการตรวจโดยผู้เชี่ยวชาญหรือการทดสอบกับผู้ใช้จริง

นำเข้าโค้ดที่ต้องการตรวจ

เลือกวิธีนำเข้าหนึ่งวิธี ทั้งสามวิธีใช้ตรรกะการวิเคราะห์ชุดเดียวกันหลังจากได้ HTML แล้ว

วิธีนำเข้าข้อมูล
ลองด้วยตัวอย่าง:
วางทั้งหน้าหรือเฉพาะบางส่วนก็ได้ หากต้องการตรวจเนื้อหาที่ JavaScript สร้างขึ้น ให้คัดลอกโค้ดจาก Inspect Element หลังหน้าเว็บทำงานเสร็จแล้วมาวางแทน
ระบบดึง HTML ต้นฉบับผ่านบริการตัวกลาง จึงตรวจได้เฉพาะเนื้อหาที่เซิร์ฟเวอร์ส่งมาก่อนที่เบราว์เซอร์จะประมวลผล หากดึงไม่สำเร็จ ให้เปลี่ยนไปใช้วิธีวางโค้ดเอง ระบบปฏิเสธลิงก์ที่ชี้ไปยังเครื่องตนเองและเครือข่ายภายในองค์กร เพื่อป้องกันการใช้เครื่องมือเป็นช่องทางเข้าถึงระบบภายใน
หรือกด Ctrl + Enter ในช่องโค้ด

สิ่งที่ระบบตรวจ

  • R-ALT-01ภาพที่ไม่มี altวิกฤต
  • R-ALT-02ภาพที่ alt ว่าง ส่งต่อผู้ประเมินแนะนำ
  • R-HEAD-01หัวข้อกระโดดข้ามระดับควรแก้
  • R-LABEL-01ช่องกรอกไม่มีป้ายกำกับวิกฤต
  • R-CONTRAST-01สีตัวอักษรต่ำกว่า 4.5 : 1ควรแก้

ผลจะแสดงด้วยสีและไอคอน

  • ผิด ต้องแก้
  • ต้องตรวจเพิ่ม
  • ผ่าน

เคล็ดลับ ถ้าหน้าเว็บสร้างเนื้อหาด้วย JavaScript ให้คัดลอกโค้ดจาก Inspect Element หลังหน้าเว็บโหลดเสร็จ แล้ววางในแท็บ “วางโค้ด HTML”

แบบประเมินสำหรับผู้ประเมิน (Checklist)

สามข้อนี้เป็นส่วนที่โปรแกรมตัดสินแทนไม่ได้ จึงต้องอาศัยดุลยพินิจของผู้ประเมิน หากยังไม่แน่ใจให้เลือก “ยังไม่ได้ตรวจ” ระบบจะตัดข้อนั้นออกจากการคำนวณคะแนน ไม่นับเป็นทั้งผ่านและไม่ผ่าน คำตอบที่เปลี่ยนจะคำนวณผลใหม่ทันที
